## 装配关系

```text
单箱
├─ 主体 ×1
├─ 前插榫 ×2
└─ 后安装挡片 ×2

侧板总成
├─ 一体侧盖板（含后M3折弯耳） ×1
└─ 前L卡耳 ×2

单箱含侧板 = 单箱 + 侧板总成
相同双箱 = 两个同样单箱，相对X平移71.2 mm
相同双箱含侧板 = 相同双箱 + 最外侧侧板总成
```

递归组件节点数包括子装配节点，不能直接当作零件采购数量：历史核验的单箱为5，单箱含侧板为10，双箱为12，双箱含侧板为17，侧板总成为3。

## 打开与手工修改

建议先只打开`全焊_单箱含侧板_草图可编辑.SLDASM`，让SOLIDWORKS加载依赖，避免把全部历史图纸同时打开占用内存。仅需观察单件时，在装配中打开对应零件。

文件曾在本机其他位置保存，首次打开若提示查找引用，应指向仓库内同名零件及侧板子目录。确认组件全部解析后再保存，避免引用到电脑上的旧版本。

模型保留草图和实体特征，已知限制包括部分草图欠约束、装配放置采用固定坐标以及部分工程图数字为二维示意标注。更改尺寸时不能假设所有文档自动同步。

槽24修订同时涉及前插榫的两张草图：

- `草图_榫槽净宽24_中线138点5`
- `草图_头部完整外形_总宽32_槽24`

只改其中一张可能使后续特征重新形成旧轮廓。原切除特征名已改为`切除_榫槽24`。

每次修改建议顺序：编辑并重建单件；检查实体与特征；重建四套相关装配；检查静态干涉、实际装入路径和关键尺寸；同步工程图关联尺寸及手写坐标文字；重新导出PDF；检查图文排版；保存并重开核对。临时图纸核验后及时关闭。

## 完整性校验

`delivery-manifest.json`记录当前15个文件的相对路径、大小和SHA-256。执行：

```bash
python tools/verify_delivery.py
```

默认发现缺失、额外文件、大小或哈希变化、内容完全相同的重复文件时会返回失败。打开CAD后出现的`~$`临时锁文件不作为交付文件。工具只读取文件，不连接SOLIDWORKS，也不改图。

有意修改图纸后，旧哈希失配是正常的版本变化。应先完成CAD和工程图检查，再评审更新清单及修订说明，不能用更新哈希掩盖未核验的改动。
